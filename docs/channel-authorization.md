# 消息渠道、规则与授权

开发维护：[设计](channel-refactor/design.md) · [计划](channel-refactor/plan.md) · [任务](channel-refactor/tasks.md) · [验证](channel-refactor/validation.md)

## 设置入口

在「配置 → 消息 & 交互」管理一组「消息渠道」卡片。点击卡片默认打开连接配置；更多菜单和弹窗切换按钮提供连接配置、通知管理、交互管理。可用页面和规则条件由该渠道的真实能力决定，不支持机器人入站的渠道只提供通知管理。

连接配置负责平台账号、凭据、接入方式与连接总开关；通知管理负责主动通知、受众和投递规则；交互管理负责首次使用、自动下载和命令。三个资源分别显式保存，切换保留草稿，不会自动覆盖另一项设置。卡片使用与其它设置页一致的新建、保存、删除和拖拽操作。

普通成员在启用智能助手时可通过受控 Agent 搜索、订阅和下载（定时任务另行开启）；未启用智能助手、未开启全局接管或显式使用 `/noai` 时，已批准的普通成员仍可在其已获授权的搜索、订阅、下载能力范围内使用传统媒体文本与按钮交互。传统管理命令、旧管理会话与管理按钮仍仅渠道管理员可用。管理员角色允许实例管理操作，设置时应单独核对。成员身份按通知实例和平台用户 ID 隔离，同一个人在不同机器人中分别授权。昵称、群组 ID 和机器人 ID 不能代替用户身份。

渠道授权和全局通知设置位于卡片组右侧。全局通知设置管理模板、通知范围和全局发送时间；渠道授权处理申请、成员能力、账号关联状态和停用。

删除连接前显示受影响的通知、交互、成员与定时任务，并核对三个资源版本。确认后直接删除连接、两个用途及排序配置。名称立即释放，同名重建使用新身份；旧授权、任务和在途消息仍绑定原身份，不能继承或重新启用。暂停使用连接总开关，保留恢复能力。

## 首次使用与允许的操作

| 策略 | 行为 |
| --- | --- |
| 人工审批 | 新成员提交申请，管理员审批后才能执行需要授权的操作。 |
| 人工审批 + 规则审批 | 当前事件命中启用规则时授予规则范围；未命中者可以申请。 |
| 规则审批 | 新成员仅在当前事件命中规则时取得规则范围。 |
| 无需审批 | 可向此连接发送消息的用户获得受控搜索、订阅和下载能力，界面显示开放风险提示。 |

首次使用规则可授予搜索、订阅、下载、定时任务。规则按连接独立保存，每条规则有名字、开关和独立编辑弹窗。用户、群组、私聊等条件仅在适配器能从已认证事件验证时提供；不能把客户端传入的群组或用户名当作证明。QQ 使用群组和用户两种条件，填写对应 OpenID。

已经批准的成员按当前审批权限使用，拒绝和停用优先。规则不会解除停用，也不会把普通成员提升为管理员。定时任务记录成员、策略版本和账号归属，创建、执行及发送结果时都复核；权限、策略或账号变化后需在有效会话重新创建。

「搜索后自动下载」按连接选择关闭、规则、全部。规则使用独立条件；全部适用于此连接中仍有下载权限的搜索用户。命中搜索结果后自动择优下载，准备完成及等待任务锁后、实际提交下载器前再次核验权限。全局 `AUTO_DOWNLOAD_USER` 不再提供或参与执行。

企业微信群组规则填写原始群 ID，不加 `group:`；Discord、Slack 使用频道 ID；VoceChat 用户使用 `UID#数字`，群组使用数字 ID。VoceChat 的指定规则需要专用回调令牌，可通过 `channel_token` 或 `X-MoviePilot-Channel-Token` 提交。通用 API_TOKEN 不授予规则中的可信事件权限。

## 通知与投递规则

全局范围仍为四种预设：仅操作用户、仅管理员、管理员 + 操作用户、所有用户。管理员是系统主管理员的通知身份；所有用户仍受启用账号、绑定地址及平台能力约束，不代表自动向平台全部成员广播。

每条投递规则选择消息类型、接收对象和通知类别。通知类别可多选管理员通知、操作用户通知、全体用户通知；空选择沿用全局范围，不能扩大全局已解析的受众。个人通知只能使用该账号的绑定地址或允许范围内的账号目标，不能被规则转发给第三方群组或用户。Web Push、AppPush 按指定账号查找已配对设备。

每类全局消息可独立配置「无操作用户时」：回退管理员或跳过个人通知，默认回退管理员。该策略不取消已经明确选择的管理员通知；账号存在但没有绑定地址、或已确定的业务归属没有可用目标时，直接跳过。

规则列表支持名字、启用状态、消息类型、接收对象类型、平台支持的精确 ID、通知范围过滤，以及导入、清空和分享。过滤不修改整组保存或分享内容，取消单条编辑不改变原规则。

投递规则的通知发送时间按系统时区、包含起止分钟，支持跨午夜，相同起止时间表示全天。实际发送须同时满足全局与规则时间窗口；窗口外直接跳过，不延后补发。相同目标的命中规则按有效窗口合并；在途重试沿用冻结的规则和已确认分段，只重试尚未确认的部分。

## 成员审批、批量管理与账号关联

用户在机器人发送「申请使用」，或点击申请按钮。网页登录的系统管理员可以通过、拒绝、停用、恢复或删除记录。允许操作按成员明确授予，普通业务能力与是否启用 AI 分离。传统管理员命令仍要求管理员权限。

待审批、已授权、拒绝和停用记录都可删除，删除已授权记录需要二次确认。删除仅撤销该授权与派生的规则任务权限，保留业务账号、订阅、下载和任务历史。重新申请获得新身份，不恢复旧关联和任务；持续禁止使用应停用成员。

批量通过、拒绝、停用和删除最多一百条。批量通过仅授予普通成员，并明确选择本次操作范围。后台在同一事务校验每条状态及版本，任一冲突返回 409，整批变更与审批回执一起回滚。审批保存成功与回执实际送达分别反馈。

机器人使用不要求预先创建网页登录账号。系统为业务记录建立内部归属，该身份不出现在网页登录用户列表，也没有密码或 PassKey。个人信息的账号绑定可生成五分钟内一次有效的关联码，在机器人已验证的私聊中发送 `绑定账号 关联码`。群聊和会话类型未知的消息不消费关联码。ClawBot、SynologyChat 当前无法验证私聊分类，不能使用机器人关联码流程，仍可手工审批。

关联同时验证两方身份，迁移成员已确认的订阅、订阅历史与下载归属；只有用户名的旧记录仍需管理员核对。执行中任务或相同订阅冲突会拒绝合并。关联不代替审批，不解除停用，关联后权限同时受网页账号和渠道授权约束。

## 身份、发送与兼容边界

个人身份按连接和平台发送者 ID 隔离，群组和线程仅用于会话与回复路由。强制私聊必须提供单个平台、实例及个人地址；失败不能回落到默认群、最近会话或其它同名实例。下载历史按不可变账号查询，当前任务还须匹配下载器、Hash 及本次提交标识，旧用户名不能证明所有权。

工具、子代理、业务 API 和定时任务在执行边界核验当前权限，后台结果发送前再次核对。已发出的外部业务请求不能通过停用自动撤销。标点或符号开头的插件输入继续走独立路由；已拒绝、停用成员仍被拦截，斜杠命令和附件不绕过权限。

正式版本的 Notifications 配置在统一迁移中直接导入最终连接及规则；投递接收人不再隐含授权。旧 QQ/VoceChat 群地址授权被隔离、移除管理员能力并暂停相关任务，不猜测群内个人身份。旧下载、订阅和无归属浏览器登记不会按同名账号自动认领。

对外 Notifications 接口与插件 NotificationConf 仍提供受限投影，稳定连接身份和独立资源版本受保护。持久化的单选通知类别和在途 Outbox 快照继续可读。它们是数据与公开接口合同，当前设置页不再回退到旧表单。

## 数据库与开发边界

统一消息渠道迁移 `62c91ad8b057`，直接接在正式版本 `c4e8f1a29b03` 之后，创建最终设备、入站去重和规则任务授权表，补齐业务归属与 Outbox 进度并导入最终配置。已经处于最终 revision 的数据库不需要重新打标。升级前备份完整数据库；涉及身份和权限的数据不可自动降级，回退须恢复匹配版本备份。其它开发快照使用配套源码或备份恢复，不手工修改 Alembic 版本号。

应用层拥有连接资源、路由和授权用例；Oper 使用调用方 Session，数据库 Adapter 管理短事务；渠道适配器只负责平台协议、真实身份及发送结果。内部渠道令牌绑定授权 ID、operation、HTTP 方法和路径，不能用于网页登录或其它路由。同步授权读取在受控 worker 中完成，固定冷导入时间预算为 3000ms。

## 渠道平台扩展边界

公共用例、授权、受众、发送时间与 Outbox 保持由宿主执行；平台身份、地址协议、凭据、诊断与特殊分段由所属模块实现。注册方式、兼容和完整调用链见[平台边界](channel-refactor/platform-boundaries.md)。
