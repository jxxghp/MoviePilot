# 通知渠道授权

在用户管理右下角点击“渠道授权”，可以统一处理申请、设置成员能力、停用或恢复成员。原来分散在各通知渠道配置中的用户和管理员白名单不再单独维护。渠道授权仅由 MoviePilot 网页系统管理员管理，渠道管理员不能继续给别人授权。

## 使用流程

用户在机器人中发送“申请使用”，或点击需要授权时显示的申请按钮。系统管理员在渠道授权弹窗批准后，机器人会向成员发送回执。批准不会自动重放之前的订阅或下载请求，用户需要重新发送要执行的操作。

普通成员通过受控 Agent 搜索、订阅和下载；定时任务另行开启。传统管理命令和旧式业务按钮仅渠道管理员可用，普通文本不再进入旧管理会话。管理员角色允许实例管理操作，设置时应单独核对。成员身份按通知实例和平台用户 ID 隔离，同一个人在不同机器人中分别授权。昵称、群组 ID 和机器人 ID 不能代替用户身份。

只使用机器人无需创建网页登录账号。系统为订阅、下载和任务保存内部归属，该身份不会出现在网页登录用户列表，也没有密码、PassKey 或网页登录能力。停用成员后，后续 API、工具、子代理和定时任务都重新校验授权；已经发出的外部业务请求不会因为停用而自动撤销。

## 关联已有账号

登录 MoviePilot 后，在个人信息的账号绑定区域生成一次性关联码。五分钟内在机器人私聊中发送 `绑定账号 关联码`；不要在群里发送。关联码只保存摘要，使用一次后失效，生成新码会撤销旧码。

关联验证账号和渠道两方身份，并迁移该成员自己的订阅与下载归属；执行中的任务或归属冲突会拒绝合并，保持原数据。关联不替代渠道审批，也不会解除停用。关联后的有效权限同时受网页账号与渠道授权限制；重新绑定不能绕过网页账号停用。

## 升级迁移

升级迁移逐实例导入 Telegram 普通用户名单，以及 Telegram、企业微信、微信 ClawBot、飞书、QQ、Discord、Slack、VoceChat、SynologyChat 的管理员名单。原默认主用户具有管理员语义的渠道会保留这项已有授权；投递接收人、群组和默认目标配置继续保留，但升级后修改这些投递字段不会自动授予权限。

已有唯一网页账号绑定保留其业务归属。重复绑定不会猜测执行账号，记录保留为待确认状态。旧任务仅在渠道、发送者和已确认执行账号都吻合时接入对应授权；无法确认的旧任务需从原会话重新创建。

旧名单清理与授权导入在同一数据库迁移事务中完成。重复升级不覆盖新授权的停用或权限调整。迁移涉及持久化业务身份，回退应恢复升级前完整数据库备份，不直接降级丢弃新表。

## 开发边界

`app/application/security/authorization.py` 拥有申请、审批和实时权限投影；`app/db/oper/authorization.py` 使用调用方 Session 暂存查询与变更；`app/db/adapters/authorization.py` 管理短事务。模型只保存数据，渠道适配器只提供平台证明的发送者身份。

内部 Agent API 令牌签名绑定授权 ID、operation、HTTP 方法和路径。每次请求重新读取当前角色与能力，不下发网页登录资源 Cookie，也不能转用于其它 API。普通成员的下载查询在分页前按归属收窄，定时任务固定授权身份与账号不可变身份。

异步 API 用户依赖和下载历史读取通过已等待的受控线程入口读取同步授权端口；每次操作在 worker 内创建并关闭独占 Session，不在事件循环执行同步 SQL，不遗留后台任务。Agent 使用现有 `db` 能力桶，取消后不提前释放底层阻塞调用名额。新增授权端点、Schema、应用服务、领域合同和 ORM 注册带来必要的冷导入模块增加；冷导入时间预算保持 3000ms。
