# 消息渠道架构设计

导航：[实施计划](plan.md) · [任务清单](tasks.md) · [验证](validation.md) · [使用说明](../channel-authorization.md)

## 资源与职责

连接、通知、交互是同一份 `ChannelSettings` 中独立保存和版本校验的资源。连接保存平台身份、凭据、接入方式和总开关；通知资源拥有投递规则和主动通知开关；交互资源拥有入站开关、首次使用策略、允许操作和自动下载规则。平台能力目录决定可以配置的条件，不从凭据或默认收件人推导使用权限。

应用层管理资源、授权、受众与投递用例；领域层定义纯身份和权限规则；数据库 Adapter 管理短事务，Oper 使用调用方 Session，不隐式提交；渠道适配器仅处理平台协议、认证事件与发送结果。设置界面由[前端仓库](https://github.com/jxxghp/MoviePilot-Frontend/tree/v3/docs/channel-settings)维护。

保存以各自 revision 防止覆盖。连接删除须同时核对三个版本，移除连接、用途及排序引用；旧成员、业务记录和在途消息仍绑定旧 ID。同名重建不能继承它们。连接总开关用于临时停用。

## 准入、权限与归属

首次使用策略为人工审批、人工审批 + 规则审批、规则审批、无需审批；拒绝和停用优先。规则只授予明确的搜索、订阅、下载或定时任务范围，不能提升管理员。搜索后自动下载按连接设置关闭、规则、全部，仍受当前下载权限约束；全局 `AUTO_DOWNLOAD_USER` 不再参与执行。

个人发言人、群组、线程和平台实例分别建模。授权按连接和真实发言人隔离；群组不能充当管理员身份。传统会话、Agent 会话、按钮和一次性选择均校验完整会话地址。规则条件只采用已认证平台事件，不信任调用者自行填写的群组或用户名。不能证明的能力不对外开放。

普通业务能力不依赖 AI 开关。API、工具、子代理和定时任务在执行边界复核当前角色、范围及账号。下载准备完成、等待任务锁之后和实际提交之前均复核授权。规则任务绑定策略版本，执行及发送结果前重新检查。已经提交的外部副作用不会因撤权自动回滚。

订阅、下载及任务保存不可变账号归属。只有用户名的旧记录留待管理员确认，不根据同名或复用主键认领。账号关联使用已验证私聊中的五分钟一次性摘要码，同时确认网页账号与渠道成员；执行中任务或归属冲突拒绝合并。强制私聊失败不回退群组或其他实例。

下载器已受理但任务尚未确认时，将原始账号归属与提交标识写入待确认快照，延迟确认时恢复。确认属于现有任务时，不以本次请求抢占既有归属。待确认保护继续阻止自动换源重复提交。

## 通知、时间与恢复

全局范围保留仅操作用户、仅管理员、管理员 + 操作用户、所有用户。规则可组合管理员、操作用户和全体通知类别，但不能扩大宿主解析后的受众。个人事件只使用本人绑定地址或允许的账号目标。无操作用户策略按消息类型选择回退管理员或跳过个人通知；明确管理员通知不被后者取消。

规则与全局发送窗口取交集，支持跨午夜；窗口外直接跳过。相同目标的有效规则按窗口并集处理。Outbox 冻结目标、规则和分段计划；重试跳过已确认分段，未知结果保留诊断。实际提交前再次检查时间、授权及业务归属。

Web Push 设备由服务器绑定当前本地账号，保存 owner、密钥与版本。普通用户不能广播。切号先注销旧端点，每个异步步骤校验账号及代次；迟到失效清理不能删除新登记。无归属的旧进程登记不参与投递，细节见 [Web Push](../webpush.md)。
