# 消息渠道实施计划

导航：[设计](design.md) · [任务](tasks.md) · [验证](validation.md)

| 顺序 | 交付物 | 验收要求 |
| --- | --- | --- |
| 1 | 平台身份、会话与业务归属 | 跨连接、个人、群组及线程不可混用，旧用户名不自动认领。 |
| 2 | 连接资源与统一授权 | 独立 revision、凭据轮换、四种准入、自动下载及规则操作范围。 |
| 3 | 通知路由与可靠投递 | 受众隔离、发送时间、冻结计划、分段重试及发送前权限检查。 |
| 4 | 生命周期与持久化 | 全量删除、正式配置导入、单一重构迁移、Web Push 设备归属。 |
| 5 | 前后端配套 | 能力目录和接口一致，显式保存与冲突反馈，共同验收桌面和移动端。 |
| 6 | 提交与部署准备 | 最终树检查、离线测试、静态门禁、关联 PR 和部署备份说明。 |

## 升级与回退

1. 备份数据库、系统配置和当前源码/镜像，保证同一恢复点。
2. 使用配套前后端与锁定依赖；由正常启动流程升级至 `62c91ad8b057`，迁移链为 `d8a4c6e29170 → c4e8f1a29b03 → 62c91ad8b057`。
3. 检查导入后的连接、主动通知目标、入站策略及待确认旧归属。被隔离的群地址不自动恢复管理员权限。
4. 浏览器在有效登录后重新登记 Web Push。按实际平台能力验收回调认证、群组/私聊和发送结果。
5. 需要回退时恢复升级前的完整数据库及匹配源码，不自动降级身份和权限数据，不修改迁移标记冒充兼容。

开发实现、离线测试和本地浏览器验收均不等于生产部署。真实平台验收和发布由部署方单独执行；当前边界见[任务清单](tasks.md)。

## 通用核心与平台实现分离

职责来源、最终 owner、完整调用链、兼容与架构边界以[平台边界文档](platform-boundaries.md)为准。

实施顺序：固定离线升级 → 规范身份与仓储契约 → 模块清单扩展与配置/规则委托 → 生命周期/附件分段 → 前端能力和表单扩展 → 有效回归/架构门禁 → 精确结果记录。交付仅限本地审阅，不自动推送、强推、合并、发布或改动手测实例。

## 独立平台边界补齐

以[独立平台验收与身份职责](platform-boundaries-completion.md)为本轮补齐设计和调用链；旧 Web 复用测试不再作为扩展完成的证据。

顺序：开放独立传输标识 → 连接/provider 定位及固定宿主解析 → 12 个内置渠道共存的认证/申请/审批/规则/拒绝验收 → 数据流架构反例 → DTO/安全政策校正 → 全量检查及实际源码索引。
