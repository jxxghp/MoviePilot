# 统一图片与附件协议

插件只调用 `_PluginBase.post_message()`，由宿主完成通知开关、接收人路由、图片获取、素材上传与平台载荷转换。
不要在插件中根据渠道选择 `media_id`、`image_key`、机器人模式或上传 API。

## 插件调用

```python
self.post_message(title="登录二维码", text="请扫码后点击完成", image=image_source, native_image=True)
self.post_message(title="字幕附件", text="请下载查看", file_path=subtitle_path, file_name="subtitle.srt")
```

`channel`、`userid`、`source`、`mtype` 等既有路由参数继续适用。省略渠道时沿用用户的通知配置，
不会因为带附件而绕过通知权限或把私聊转为群发。

| 参数 | 统一含义 |
| --- | --- |
| `image` | 默认是原有通知封面；使用 `native_image=True` 时表示独立原图 |
| `native_image` | 默认 `False`；`True` 请求完整图片，支持上传的渠道接受 HTTP(S)、Base64 数据地址或本地 JPG/PNG |
| `file_path` | 本地附件路径，发送后保留源文件 |
| `file_name` | 可选的接收端展示名称，默认使用源文件名 |
| `title` / `text` | 图片或附件的说明，不因发送附件而忽略 |

原图输入须大于 5 字节且不超过 10 MiB，不裁切或改写源图片字节。接收端仍可能生成自己的预览图。
只接受路径上传的客户端使用运行时临时目录内的短期副本，上传结束即清理；不会删除调用方文件或写入图片缓存。
图片与文件同时存在时分开发送，说明和交互按钮只随第一部分发送，不因某个渠道的文件分支而静默丢图。

## 当前渠道适配

下表描述当前宿主接入实现，不等同于平台所有 API 的能力。实际尺寸、配额、账号权限和服务端拒绝由对应客户端处理。

| 渠道 | `native_image=True` | `file_path` |
| --- | --- | --- |
| 企业微信自建应用 | 上传 JPG/PNG 后发送 `image`，说明另发文本 | 上传临时素材后发送 `file`，不超过 20 MiB |
| 企业微信智能机器人 | 长连接分片上传后发送 `image`，说明另发 | 长连接分片上传后发送 `file`，不超过 20 MiB |
| Telegram | 上传原图，保留会话、话题及按钮 | 复用已有附件上传 |
| 飞书 | 上传后发送独立 `image`，说明及按钮另发 | 复用已有附件上传 |
| Slack | 上传原图，不依赖外部图片地址公开访问 | 复用已有文件上传 |
| Discord | 上传原图，保留接收会话 | 复用已有附件上传 |
| 微信 ClawBot | 上传图片，并保留说明 | 复用已有附件协议，保留说明 |
| 钉钉、QQ、SynologyChat、VoceChat | HTTP(S) 图片沿用现有行内图片；本地或 Base64 来源明确提示暂不支持 | 当前宿主接入暂不支持，发送明确提示 |
| WebPush、AppPush | 保留现有系统通知行为，原图请求降级为图片链接或明确提示 | 当前宿主接入暂不支持，发送明确提示 |
| Web / WebAgent | 沿用站内消息及 Agent 回调的图片展示 | WebAgent 使用已有附件回调；普通站内通知不提供本地文件上传 |

普通通知中的 `image` 和 `native_image=False` 保留旧行为，包括企业微信 `news` 海报卡片。
显式原图不把插件默认详情链接变成图片点击目标。只有链接图片能力的渠道仍可能需要一个能被客户端访问的 HTTP(S) 地址。

文件不支持时通知中显示“附件未发送”及展示名称，不发送原始本地路径，不伪造附件下载链接。
原图不支持上传时使用现有行内图片或图片链接；Base64 和本地路径不会作为文字发送给接收者。
下载、上传或发送失败保留错误信息，接口入队不代表远端已经收到。离线测试与 CI 不能替代真实账号验收。
