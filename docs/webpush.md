# 浏览器通知账号归属

浏览器订阅绑定服务器读取的当前启用本地账号，使用该账号的不可变通知身份。改名不改变归属；账号停用后停止投递，删除账号时级联删除设备。同名或同主键重建的账号不会继承旧设备。内部渠道账号不能登记浏览器通知。

浏览器在登录后向 `POST /api/v1/message/webpush/subscribe` 发送当前 `PushSubscription` 的 `endpoint` 和 `keys`：

```json
{
  "endpoint": "https://push.example/subscription",
  "keys": {"p256dh": "browser-public-key", "auth": "browser-auth-secret"}
}
```

请求接受这两项字段及浏览器原生 `toJSON()` 的可选 `expirationTime`，后者不参与归属或存储。`owner`、`user_id` 等客户端归属参数返回 `422`；服务端不会相信用户名或客户端保存的账号身份。端点要求 HTTPS，两个密钥必须完整提供。响应使用既有 `Response` envelope，成功时为 `{"success":true}`，不返回 owner 或密钥。

同端点同账号登记按端点幂等更新，每次生成新版本。同端点改绑其它账号时，需要当前有效登录和现存订阅两个密钥完全一致的持有证明；不匹配返回 `409`，不覆盖原账号登记。浏览器应重新读取 `pushManager.getSubscription()`，必要时取消旧浏览器订阅并重新创建，不应猜测或编辑密钥。订阅密钥具有设备换绑能力，不记录到日志、不与其它浏览器共享。

主动退出先同步撤销浏览器共享的通知代次，再在保留旧 Bearer 身份的请求中调用 `POST /api/v1/message/webpush/unsubscribe`，同时取消本机订阅。退出立即清除网页登录状态，不依赖服务器在线；本机取消或服务端撤销未完全确认时会显示提示，不能宣称服务器已解绑。旧后端缺少注销接口也会取消本机订阅。仅当前账号且密钥匹配的设备会被服务器取消；跨账号和重复取消返回相同成功响应且不产生副作用。

前端允许所有已登录本地账号登记。浏览器同源标签页共享一个通知账号标记（账号 ID、随机代次及轮换状态，不存令牌、密钥，也不参与服务器授权）。后台刷新和旧会话恢复不能夺回其它账号的通知；明确登录或点击启用才能选择新通知账号。切号先取消旧端点再创建新订阅，逐个异步步骤复核账号和代次；旧请求即使已提交，也只能登记已经取消的旧端点。支持 Web Locks 时额外串行各标签页操作；不支持时仍依赖共享代次与旧端点取消。共享存储不可用时不自动登记，需恢复浏览器站点存储后重试。令牌刷新和同账号恢复保留端点，重启或认证失效不会被当成用户主动注销。

个人、管理员及显式所有用户通知都使用通知链已选择的不可变账号目标；缺少目标不会隐式广播。超级管理员专用的 `POST /api/v1/message/webpush/send` 独立选择当前有效账号的全部已归属设备。普通用户不能调用它。两条路径都不使用旧无归属登记表。

新登记写入 `webpushsubscription` 表，进程重启后保留。404/410 清理同时比较端点、owner 和登记版本；旧网络请求的迟到失败不会删除重新登记或换号后的新设备。其它失败保留登记等待后续处理。

注册阶段只核验 HTTPS 报文格式，不进行 DNS 或远端连接。每次实际发送前，协议发送器复用宿主 URL 安全策略拒绝非公网、混合和不可解析的 DNS 结果，并禁止 HTTP 重定向。响应正文和底层网络异常中的完整地址不会进入推送错误日志。DNS 安全校验与 HTTP 建连没有绑定同一解析结果，仍存在检查和使用之间的 DNS 变化窗口；本变更不声称消除了 DNS 重绑定风险。

统一消息渠道迁移 `62c91ad8b057` 建立设备归属表。对外已存在的 `global_vars.SUBSCRIPTIONS`、锁和登记方法保留进程 ABI，但无归属登记不会导入新表或参与投递；浏览器必须在有效登录后重新登记。身份和权限迁移不支持自动降级，回退需要恢复升级前完整数据库备份。
