# 订阅补全搜索与手动分页

“设置 → 订阅 → 基础设置”的“补全搜索策略”使用 `SubscribeSearchStrategy`：`smart`（默认）智能搜索，`full` 全量搜索，`single_page` 仅搜索第一页。它作用于新建订阅和补找缺失资源，包括手工、定时及恢复触发的订阅搜索；日常获取最新资源仍由“订阅模式”控制。

智能搜索兼顾补齐速度与资源选择。全量搜索收集各来源全部结果页后择优，资源较多时可能耗时很长，并延迟开始下载。单页搜索每个站点实际关键词只检查第一页，保留别名回退，但过滤不通过或下载明确失败也不自动请求后页；它可能遗漏较早剧集和其他版本。检查过配置范围与站点真实搜尽分别记录，服务重启仍保留单页限制。

电影、整季和按集洗版始终完整分页。智能和全量策略不受 `SEARCH_RESOURCE_PAGES` 限制，但每个来源最多请求 100 页，防止异常站点或缺陷导致无限翻页；该环境变量仍用于既有同步、异步、SSE 和插件搜索入口。未设置时为智能。音乐、字幕、RSS、最新种子浏览保持原有策略。

## 收集与下载

一个来源是站点和实际关键词的组合，各集共用该来源的一条游标。资源按原搜索去重规则（站点名 + 标题 + 描述）去重，每页只识别新出现的资源。电影按作品、电视剧按作品/季/集收集；分辨率、免费、制作组等下载条件不会把“出现”改成“没有出现”。从未出现的缺集继续寻找；已出现目标在之后完整一页明确缺席，才结束该来源的主动收集。失败或不完整页不作为缺席或末页。站点越过末页或实际不支持分页时可能重复返回同一页：任一页与上一页内容完全相同即按空页（末页）处理。

一个目标在所有计划参与的正常来源都结束收集或搜尽后，才择优提交。来源失败会明确展示，不无限等待。其他缺集推进分页时遇到已关闭目标的新候选，在尚未提交前仍能参与择优。启用多名称时所有名称参与屏障；未启用时保留别名回退。没有合格候选或明确下载失败时，从共享当前游标继续完整兜底，兜底中的集等相关来源翻完后再择优。本轮已处理过（被下载条件淘汰、已提交或下载失败）的候选只在内存中记录，本轮不再重复处理；时间片切换或重启后按最新信息重新判断，跨轮次的下载失败由原有下载失败冷却负责。智能模式不保证后续所有页面中的最优版本。

覆盖尚未就绪缺集的合集暂缓；已就绪单集可先提交。合集覆盖目标就绪后一次提交。普通订阅已经确认提交的集不会因为后页更优版本再次下载。空缺集列表表示整季；有可信范围时展开，否则完整搜索。

分页只决定何时交付哪批候选。媒体匹配、季集范围、过滤与排序复用原搜索规则；下载选集、缺集计算和订阅完成判断复用原订阅下载流程。每批传给原下载链的缺集先去掉本轮已提交的集，中间批次写入的缺集数因此准确。仅本批覆盖部分剩余缺集时，展开已知缺集并传入本批允许集数，在插件完成资源选择后与最终候选的限制取交集；本批已覆盖全部剩余缺集时不加限制，完全沿用原下载行为（含整季包整包下载），整季洗版保留原完整覆盖要求。原下载链返回的剩余缺集仍是完整的，不能把“本批已下载完”当作“订阅已补齐”。

## 中断与流控

每页的候选、识别缓存和下一页一起保存在 `searchsession`（每个订阅搜索任务一行），通过版本 CAS 和队列任务租约隔离迟到 worker。系统停止、时间片和站点冷却保留未结束任务；主动取消不会自动恢复。任务约 60 秒在页面安全边界让出机会，现有队列约 10 秒检查是否可执行。

自动同站最多一个请求在途，间隔至少 10 秒，站点更严格的间隔/窗口和既有错误退避优先；不同订阅共享额度。等待任务只重新入队，不占用线程休眠。手动翻页不进入该自动队列，仍遵循站点既有请求检查。

中断后恢复时，检查点超过 36 小时未更新就丢弃旧进度重新搜索，已提交的集保留。不到 36 小时时，某来源距上次请求超过 15 分钟（冷却、排队或重启之后），先接着拉原来的下一页，下一次请求再重拉第一页补入新资源，之后从原页码继续；这样每次重拉前至少推进一页，间隔一直很长时也不会卡在第一页。连续翻页不会触发；重拉请求失败时放弃本次重拉。重拉的第一页与续翻页面都按去重键去重，已见过的资源（包括第一页置顶）只算一份；重拉的第一页不作为任何集的缺席证据。中断期间新上传会把旧资源往后挤，续翻时重复看到的几条会被去重；新上传超过一页时，后续页的新资源交由日常订阅获取。

已提交进度只属于检查点记录的媒体来源、作品 ID、类型、季和剧集组；更换其中任一项时清除旧作品的进度。同一作品修改关键词等搜索条件可重搜，但保留已提交的集。不兼容旧格式检查点。

下载提交沿用原有订阅下载流程：下载器返回任务 hash 即成功；没有 hash 视为失败并尝试下一个候选。已提交的目标在本轮不再重复提交；每批使用原下载链返回的剩余缺集结算，本轮结束再按当前订阅只读计算缺集后判断完成，不用搜索开始时的旧媒体快照回写总集数。

检查点只保存未结束的搜索：本轮正常结束时删除该任务的检查点（需仍持有任务租约）；被取消任务遗留的检查点暂不清理。检查点不保存 Cookie、API Key、passkey 或携带凭据的下载配方。可重建的票据使用当前配置；其他临时票据按原来源页重新取得，但不会回退历史分页游标；原页暂时无法重取时等待后重试。

本轮到末页仍缺集时结束本轮，保留订阅；不会因为缺集自动循环重扫历史，也不新增日/周复查。现有明确搜索触发和 RSS/订阅抓取继续工作。分页进度（已搜索页数、已提交与仍缺集）只写入日志，订阅执行状态接口保持原样。

## Web 手动分页

新搜索默认每个实际来源只请求第一页。点击结果底部“继续加载”或顶部“重新搜索”旁的续页图标时，每个未结束来源加载自己的下一页；失败来源保留页号供下次点击重试。两个入口共用加载状态与页号，不能重复推进。每个来源最多加载 100 页。新增分页没有预取、滚动自动加载、后台翻页或自动重试；别名回退只在首次请求时进行。SSE 断流后回退到原普通请求，此时不提供续页。按钮依赖原始来源分页状态；过滤后零条不会隐藏。续页将新结果追加在末尾，不主动滚动；用户调整排序条件后再按所选条件重排。

页号由前端按来源维护，后端只缓存按本轮来源和页号区分的原始页摘要（36 小时），不保存手动搜索候选或推进客户端游标；多页结果不做逐条去重，整页与上一页完全相同时按末页处理；续页不覆盖“上次搜索”缓存。智能推荐只覆盖首次搜索结果：续页不清空、不重新触发推荐；续页期间推荐完成时，续页结果仍接在完整原始结果之后；筛选结果全部来自续页时不发起推荐并提示。手动分页与自动订阅共用来源、单页请求（`SearchSources`）和原始页摘要规则；取得原始结果后，分别调用原标题搜索或媒体搜索的结果处理，保留指定季（包括第 0 季）等既有语义。手动分页不使用订阅的智能收集、站点预算队列或检查点，只遵循站点既有请求间隔。

## 接口与验证

`/search/title/stream`、`/search/media/{id}/stream` 在 `manual_paging=true` 时启用单页模式：首次请求（不带 `source`）每个来源请求第 0 页；`replace` 和 `done` 带 `sources`，每个来源有不透明标识 `source`、`site_name`、本次 `page`、是否允许继续请求 `can_continue` 和 `error`。客户端仅在整页结果收齐并应用后推进页号，分块未收齐或单独的 `done` 不推进；继续加载时只回传 `source` 和指定 `page`，不传 `prev_signature`，响应也不返回 `signature`。

后端页摘要有效期沿用 36 小时，按本轮来源与页号分别保存，重试第 N 页仍与第 N-1 页比较。上一页摘要过期或丢失时先请求第 N-1 页，再请求第 N 页，仅目标页进入原识别、过滤和排序流程并返回。补上一页也遵守站点原有请求间隔和超时；任一步失败保留目标页号供用户重试，不自动重试。第一页无需补页；达到 100 页上限时直接结束，不再补上一页。缓存使用现有内存/Redis 门面，不新增数据库表或手动会话接口。

缓存过期即不再参与比较；Redis 按 TTL 清理，内存缓存沿用后续写入时回收过期项的机制，且该缓存区最多保留 1024 条页摘要。没有额外的定时清理任务，空闲时不保证在过期瞬间释放内存。

后端共用原搜索去重键（站点名 + 标题 + 描述）计算摘要，并按原顺序比较整页，保留重复项。原始页为空、与上一页完全相同、站点明确返回末页、不支持分页的首页已成功，或达到 100 页上限时停止该来源。真实站点请求失败允许原页重试，包括不支持分页的站点；插件仍只参与首次请求。`can_continue=true` 表示可以继续尝试，不保证下一页有资源，也不预取下一页；显示过滤后的数量不影响判断。客户端不解析 `source`，不需要知道站点关键词或别名。手动接口不返回 `next_page` 或 `has_more`；站点内部的 `has_more` 仍作为已知分页事实使用。默认参数、同步 HTTP 接口、Agent operation 和插件返回合同不变。

自动化验收使用隔离 pytest、模拟站点/下载器和前端交互测试，不请求真实 PT 或下载器。实际站点和浏览器联调证据须单独报告，不能以模拟测试代替。
