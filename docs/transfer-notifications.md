# 整理成功通知粒度

系统设置 → 高级设置 → 实验室中的“按批次聚合整理成功通知”默认开启，
对应 `TRANSFER_SUCCESS_NOTIFICATION_AGGREGATION=true`。一张分轨专辑的任务全部结束后，
按下载器/种子、目标媒体目录、季和用户合并成一条成功通知。没有下载 hash 时按源目录分组。
单文件与多文件汇总均使用用户配置的入库成功通知模板（`organizeSuccess`），
不在发送代码中固定标题和正文。聚合后向模板提供实际入库文件数（`file_count`）、
总大小（`total_size`）、音乐专辑及已知总曲目数（`album`、`total_tracks`）、
电视剧季集范围（`season_episode`）等上下文；最终文案和排版由模板决定。
目标目录可从 `__transferinfo__.target_diritem.path` 读取。
多文件通知保留“查看整理记录”入口；整目录或手动整理的明确批次结束即发，即使只有一个文件。

电影、电视剧和音乐使用同一个全局开关。关闭时保持原有按媒体作业发送的行为。
目录设置继续使用原来的“发送通知”开关（`notify: true/false`），不增加通知粒度设置。
批次聚合只影响展示消息，逐文件整理历史、完成/失败事件、刮削和种子状态回写保持原流程。
失败通知仍由独立的失败聚合开关控制。

目录监控等自动单文件入口在各自批次结束后采用三十秒静默窗口，
同组后续文件会重置窗口，将连续入库的同季剧集合并为一条通知并汇总集数、文件数和大小。
没有明确批次的外部任务同样采用三十秒静默窗口。
窗口内若还有同组批次未结束，会继续等待；不同来源、目标目录、季和用户仍分别通知。
明确批次等待登记关闭且所有任务终结，较慢的曲目不会打断汇总，失败任务不会计入成功文件数。
前台手动整理仍不发送成功通知。关闭进程时在整理 worker 收敛后刷新剩余缓冲。
通知缓冲是内存展示状态，异常退出不保证重发此前已完成任务的成功通知；逐文件历史仍可查询。
